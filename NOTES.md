# NOTES: design decisions and gotchas

For whoever (human or Claude) continues this project. Author: leone007. Server: Unraid 7.3.3 ("JELLYNAS"), web UI on port 180. Language of the owner: Hungarian; the UI of the plugins is English, the Discord messages are Hungarian or English (setting).

## Layout and build
- `diskbox/` and `sysbox/` have real sources and a `build.py` that writes `dist/<name>.plg` (everything is embedded in the `.plg`, as CDATA). `seedbox/` is built from `seedbox/template.plg` (placeholders `@@SRC:path@@`) by `seedbox/build.py`; `streambox/` exists only as `.plg` (the files in its folder are unpacked copies, `tools/extract_plg.py`).
- `common/discord_tpl.php` is the template of the Discord helper; `tools/gen_discord.py` writes `diskbox/discord.php` and `sysbox/discord.php` (prefixes `dbn_` / `sxn_`).
- `build.py` has a FILE list and a titles list that must stay the same length (there is an assert on the count). A file containing `]]>` cannot be embedded in CDATA (asserted).
- Version entity in `build.py` (`2026.10.08c` style) and a `<CHANGES>` entry on every release. After a change: build, XML parse, `php -l` on every embedded PHP file, `node --check` on the page JavaScript.
- `pluginURL` is the raw GitHub URL `https://raw.githubusercontent.com/leone007/unraid-mediaserver-tools/main/dist/<plugin id>.plg` (since 2026-10-18: Seedbox 2026.10.99zu, Sysbox 2026.10.22h, Diskbox 2026.10.22e, Streambox 2026.10.14h, Monitor 2026.10.07f). The dist file name must be the plugin id (`qbittorrent_widget.plg`, `mediaserver_monitor.plg`), or a fresh install from the URL would land under another file name. The old local `php -S` update server (ports 18181-18185, repo.php) is gone; these versions still pkill it and remove repo.php once. An update shows up on the Plugins page only after the new `.plg` is pushed to main.
- Install command used on the server: `cp .../x.plg /boot/config/plugins/x.plg; md5sum ...; rm -f /var/log/plugins/x*; /usr/local/sbin/plugin install /boot/config/plugins/x.plg`. **The installer deletes `/tmp/<name>_*` files: do not update Diskbox while a Balance move is running.**

## Unraid specifics
- Dashboard tile: `.page` with `Menu="Dashboard:0"`, tile HTML in a PHP heredoc, then `<style>` and `<script>`; settings: `.page` with `Menu="Utilities"` (they appear on the Settings tab, Utilities section).
- AJAX endpoints check CSRF: either the `csrf_token` (when present) or the `X-Requested-With: XMLHttpRequest` header (Unraid removes the token from `$_POST`).
- In the web context `PHP_BINARY` is php-fpm, not the CLI: use `db_php()` (`/usr/bin/php`) to start CLI scripts.
- Cron: write `/boot/config/plugins/<name>/<name>.cron` and run `update_cron`; the link in `/var/log/plugins` exists only after the install scripts end (wait for it in the background).
- Disk data: `/var/local/emhttp/disks.ini` (`fsSize`, `fsUsed` in KB), `var.ini` (`mdState`, `mdResync*`, `csrf_token`).

## Discord alerts (Diskbox and Sysbox)
- Cron every minute runs `notify.php`; state lives on the flash (`notify_state.json`, written only when it changes), debounce counters in `/tmp`.
- `*_track()`: sends on new, escalation or signature change, optional repeat of red alerts every `n_remind` hours, all-clear on resolve. Hysteresis is applied by the callers (temperature -2 C, fill -2, RAM/storage/CPU -3).
- Colours: red `E5534B`, amber `D9921F`, green `3FA24A`, blue `4A90E2`. Ping (`dc_ping`: user ID, `role:ID`, `@here`, `@everyone`) only on red alerts and the test message.
- Diskbox runs `api_fetch.php` through the CLI php so the tile and the alerts classify the same way.

## SMART in Diskbox
- `smart.php` (every 20 minutes, never wakes a spun-down disk) stores per attribute `[id, name, prefail, raw, value, worst, thresh, failed]` for ids 5, 10, 184, 187, 196, 197, 198, 199. Pre-fail vs Old age comes from the attribute flags. 188 is excluded on purpose (packed raw value).
- Acknowledge (`ack.json`): an attribute counts again only when its raw value rises above the acknowledged one. A failed health check cannot be acknowledged.
- Worsening after an acknowledgement: reference time is the acknowledgement or the previous alert; within 7 days or by 10 or more = rapid (red, ping), otherwise slow (amber, no ping). The weekly summary lists acknowledged warnings.

## Balance (Diskbox 2026.10.08)
- Why: hardlinks work only inside one filesystem, so the downloads file and its media hardlink must always move together to the same disk.
- A unit is a top-level entry of a configured downloads folder; its media links are found **by inode** (the media names differ, Radarr/Sonarr rename). Units are skipped when the inode has links outside the configured folders, the unit shares a file with another unit, the download looks unfinished (`.!qB`, `.part`, ...) or files changed in the last 2 hours.
- Plan: target fill = equal fill (array average) or the owner's value if reachable; greedy assignment from the fullest disks to the emptiest; the page lets the user tick titles and change the target disk. Plan files live in `/tmp` (`diskbox_balance_*`).
- Move (`balance_run.php run`, background, flock): per unit one `rsync -aH --from0 --files-from` (hardlinks are recreated because all names of an inode are in the same run), then verification (size, same inode on the target for all names of a group, link count), then removal of the source files and of directories that became empty (never the configured roots). On any failure the copy on the target is removed, the source is untouched and the run stops. Refuses to run during parity check/rebuild/mover or with the array stopped.
- Discord: start, finish (amber when titles were skipped), error (red, ping). The tile shows a Balance card while it runs and for 24 h after.
- Tested only with a fake disk tree and a shim instead of rsync, then on the real server with single titles (9 GB, 28 GB) before the big run. Not handled: files hardlinked outside the configured folders (skipped), power loss mid-run (the next run re-checks; look for a half-copied title on the target).
- Possible future work: select-by-share filter, schedule, configurable thresholds for the rapid-worsening rule, per-disk target fill.

## Seedbox tools (Seedbox 2026.10.07)
- Page Settings, Utilities, Seedbox Tools (`SeedboxTools.page`), endpoint `tools.php`, long jobs in `tools_run.php find|upd|search <hash>|tick` (started with setsid, one flock per mode), logic in `tools_ops.php`, helpers in `tools_lib.php`. Config `tools.json` (API keys, mode 600) and state `tools_state.json` (ignored folders, pending adds, replacement jobs) live in `/boot/config/plugins/qbittorrent_widget/`; scan results are in `/tmp/qbt_tools_*.json`. Cron (every minute) runs `tick`, which returns at once when nothing is pending.
- **Find my torrent**: units are the top-level entries of the configured downloads folders; a unit is seeded if some torrent's `content_path` (mapped from the container path, default `/data` to `/mnt/user/data`) equals it or lies inside it. Torrents whose tracker answers "unregistered" etc. (only checked when qB reports no working tracker) are listed too. Prowlarr search with the release name, then title and year; a candidate is shown when the normalised name matches or the size is within the tolerance (default 1 percent bigger, 2 percent smaller). Add: download the .torrent (or magnet), add stopped, recheck; `tick` starts it only at 100 percent, otherwise removes it (files kept); for a dead tracker the old torrent is removed (files kept) after the new one is seeding. Both `paused` and `stopped` are sent because qBittorrent 5 renamed the parameter; `start` falls back to `resume`.
- **Update me**: torrents that are big and old (settings) or dead are matched with Radarr (movie file size equals the torrent's only video file) or Sonarr (episode file sizes of one season; several seasons are not supported). Search is Radarr/Sonarr's interactive search (`/release`); filter: resolution not lower, HDR rank not lower (DV 3, HDR 2, SDR 1, from the release title), at least the saving percent smaller (not for dead torrents). Replace = POST `/release`. `tick` follows the queue (importBlocked is shown with the message) and the file ids to detect the import; removing the old torrent plus files is a separate confirmed click and only after the import.
- Caveat to verify on the real server: Radarr/Sonarr may refuse to import a manually grabbed release as "Not an upgrade" (profile/cutoff); then the user imports it by hand in the queue. A later version could trigger a ManualImport command. Tested only against mock servers (qBittorrent, Prowlarr, Radarr), not against the real services.

## Sysbox Safe shutdown (2026.10.10)
- Page `SysboxShutdown.page` (Utilities), endpoint `shutdown.php` (state, stop, start, cancel, kill), worker `shutdown_run.php stop|start` (flock `/tmp/sysbox_shutdown.lock`, status `/tmp/sysbox_shutdown.json`).
- It never unmounts or stops the array itself: the final buttons post `cmd=shutdown|reboot` with the csrf token to Unraid's `/webGui/include/Boot.php`, which runs `/sbin/poweroff -n` or `/sbin/reboot -n` (seen in the 7.3.2 webGui).
- Holders: every /proc/PID with an fd, cwd or mapped file under /mnt (not disks, remotes, addons, rootshare). Protected (listed, never signalled): PID 1-2, Unraid services (emhttpd, shfs, dockerd, containerd, libvirt, qemu, Samba, NFS), processes inside a container (cgroup docker id), mover, rsync while Diskbox Balance runs. A signal goes only to a PID that is in a fresh scan with the same start time (field 22 of /proc/PID/stat) as the page showed.
- Containers: qBittorrent (name or image matches) first with `docker stop -t 300`, then the others in one `docker stop -t 60`; stopped names are kept so 'Start them again' starts exactly those; they are marked in `/tmp/sysbox_userstop.json` so the Discord alerts stay quiet. VMs: `virsh shutdown`, wait 180 s, never destroyed.
- The stopped list in `/tmp/sysbox_shutdown.json` survives an array stop/start (2026.10.22g): `sd_prune()` in `shutdown.php` compares it with `docker ps -a` on every state read and on Start them again (running = `back`, missing = `gone`, only the rest stays `stopped`); an empty Docker answer keeps the list unchanged.
- Tests: `SX_SD_DIR`, `SX_SD_MNT`, `SX_SD_DOCKER` (also honoured by `sx_docker()`), `SX_SD_VIRSH`.

## Update me offers (Seedbox 2026.10.99d, item 28)
- The scan still only picks candidates (done, at least upd_min_gb, at least upd_min_age days, or removed by the tracker); the end of `st_upd_scan()` spawns `tools_run.php updbg` (`st_upd_bg()`, own flock), which searches one listed torrent every ~90 s with the normal `st_search_item(..., 'upd')` and stops when every matched torrent has a fresh result (ready: 10 days, error: 1 day). Stop: `/tmp/qbt_tools_updbg.stop` (op `upd_bg`). Progress `/tmp/qbt_tools_updbg.json`; `upd_get` recounts done/total from the results.
- `st_search_item` in upd mode: lower resolution or HDR format is always dropped; a row gets `cats`: `save` (saving reached, with 1e-9 for float rounding), `hdr` (better HDR, size within upd_upg_growth %), `res` (higher resolution, same size limit); no category and not dead = dropped. Rows sort by [hun, hdr, res, size] desc. Switches `upd_cat_save|hdr|res` (at least one), `upd_upg_growth` (0 = no limit, default 100).
- Results are written with `st_res_set()` (lock `/tmp/qbt_tools_res.lock`) by the page ops too; each result carries `mode` (upd / repl).
- 99e: the progress line adds the balance: per torrent the first listed `save` row frees cur_size - size, the first `hdr`/`res` row takes size - cur_size (can be negative); follows the filter chips (UCAT). Marked approx.: hardlinked files free space only when every link is gone.
- The Seedbox installer removes only `/tmp/qbt_widget_*`, NOT `/tmp/qbt_tools_*` (results, lists, autobrr marker survive an update). A running `tools_run.php updbg` kept its old code across updates; since 99i the install script runs `pkill -f "qbittorrent_widget/tools_run.php updbg"` (safe: read-only searches, atomic JSON writes).
- Unraid 7 settings layout (default-base.css): `dl` is a grid (35% / 1fr from 769 px), every `dd` is `display:flex; flex-direction:column; gap:.5rem` and its inputs/selects get `max-width:400px` (`.narrow` 150px). Inline controls in one dd therefore stack; a page that wants them on one line overrides `dd` with `flex-direction:row; flex-wrap:wrap` (Seedbox 99n) and uses a full-width element instead of `<br>` (a `<br>` does nothing in a flex row).
